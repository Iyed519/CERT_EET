# US-UX-02 — Navigation latérale par rôle, groupée, avec icônes et compteurs

## En une phrase
Le formateur et l'administrateur ont désormais un menu latéral fixe qui range leurs fonctions par
thème (Enseigner, Évaluer, Suivre… / Personnes, Formations, Certificats, Pilotage, Sécurité), chaque
entrée avec son icône et, quand quelque chose attend, un compteur rafraîchi sans recharger la page ;
réductible aux icônes, en tiroir sur mobile. L'apprenant et le visiteur gardent l'en-tête d'avant.

## Décisions (table D, écrite avant de coder)
| # | Point | Options | Décision |
|---|---|---|---|
| D1 | Arborescence du formateur | celle de la spécification ; ajustée | **Accueil** · **Enseigner** : Mes formations, Demander une formation, Proposer une formation · **Évaluer** : Livrables à corriger, Tentatives des QCM · **Suivre** : Apprenants, Alertes, Rapports · **Explorer** : Catalogue. Adresses existantes inchangées. Trois entrées n'avaient pas de page d'ensemble (les livrables, les tentatives et le suivi n'existaient que par formation, atelier ou QCM) : trois **pages nouvelles** (D4), aucune supprimée. |
| D2 | Arborescence de l'administrateur | — | **Accueil** · **Personnes** : Comptes, Demandes de rôle · **Formations** : Formations, Demandes d'affectation, Propositions · **Certificats** : Certificats · **Pilotage** : Rapports, Prédiction du risque, Générations IA · **Sécurité** : Journal d'audit. |
| D3 | Entrée active | préfixe le plus long ; motifs | Chaque entrée déclare ses motifs (`/formateur/formations/*`, `/formateur/qcm/:id`, `/formateur/formations/:id/suivi`…) ; l'entrée active est celle du motif **le plus précis** qui correspond (segments fixes d'abord), ce qui distingue « Mes formations » (éditer un QCM) de « Tentatives des QCM » (`/formateur/qcm/:id/tentatives`) et d'« Apprenants » (suivi d'une formation). Fonction pure `entreeActive`, testée. |
| D4 | Pages d'ensemble nouvelles | lien vers le tableau de bord ; pages | `/formateur/livrables` (ateliers de mes formations avec livrables à corriger, en correction, notés → page de l'atelier, filtre « À corriger » existant), `/formateur/qcm` (QCM de mes formations : tentatives, à évaluer, alertes IA à examiner → historique des tentatives ou éditeur), `/formateur/apprenants` (une carte par formation : inscrits, actifs, alertes → suivi pédagogique, rapports ; données du tableau de bord existant). Les pages par objet restent les mêmes. |
| D5 | Compteurs | appels existants ; point d'API en lecture seule | Les appels existants (tableau de bord complet, liste d'alertes) sont trop lourds pour être rappelés à chaque page et toutes les minutes : **`GET /api/navigation/compteurs`** (formateur ou administrateur, lecture seule, non tracé, une requête SQL par rôle). Formateur : alertes de décrochage ouvertes, alertes de surveillance à examiner (somme affichée sur « Alertes »), livrables à corriger (SOUMIS ou EN_CORRECTION, comme le tableau de bord), tentatives à évaluer. Administrateur : demandes de rôle, d'affectation et propositions en attente. Mêmes définitions que le tableau de bord et « À faire maintenant » (vérifié en e2e). |
| D6 | Données des pages d'ensemble | assembler côté web ; point d'API | **`GET /api/formateur/evaluations`** (formateur, lecture seule) : comptes agrégés par atelier et par QCM sur ses seules formations affectées, deux requêtes SQL (pas de N+1). C'est la même famille que les compteurs (des nombres, regroupés par objet) : aucune donnée qu'il ne voyait pas déjà dans chaque page d'atelier ou de QCM. Aucune autre réponse ne change. |
| D7 | Rafraîchissement | WebSocket ; relecture | Relecture à chaque changement de page, au retour sur l'onglet du navigateur et toutes les 60 s ; un compteur à zéro n'est pas affiché ; échec silencieux (le menu reste utilisable). |
| D8 | Mise en page | grille ; menu fixe | Menu `aside.nav-laterale` en position fixe sous l'en-tête (≥ 1 024 px), le corps de page décalé de sa largeur (`body[data-nav-laterale]`). Réduit aux icônes (72 px) par un bouton en bas du menu, choix mémorisé (`localStorage`, lecture protégée) ; infobulle au survol et au focus sur chaque icône, nom accessible conservé. |
| D9 | Mobile (< 1 024 px) | menu déroulant d'avant ; tiroir | Le bouton menu de l'en-tête ouvre un **tiroir** à gauche avec les mêmes groupes (et la recherche) ; fermeture par Échap, la croix, un clic sur le voile ou un changement de page ; focus placé dans le tiroir puis rendu au bouton. Apprenant et visiteur : menu déroulant inchangé. |
| D10 | Doublons | garder ; retirer | Pour le formateur et l'administrateur, les liens de l'en-tête sont remplacés par le menu latéral ; la sous-navigation d'administration (onglets Comptes / Demandes de rôle…) disparaît, chaque page ayant son entrée ; le menu du compte garde « Changer de rôle » (formateur), « Sécurité du compte » et « Se déconnecter », ses autres liens étant des entrées du menu latéral (mêmes adresses). Les onglets « Décrochage / Surveillance des QCM » de la section Alertes restent (ce sont deux vues d'une même entrée). |
| D11 | Fil d'Ariane | inchangé ; aligné | `filAriane` suit le menu latéral pour ces deux rôles : « Accueil › entrée active › … » ; l'apprenant garde le sien. |
| D12 | Inventaire | — | La comparaison tient compte de la coque (menu latéral, menu du compte) : une action de la coque est atteignable depuis toute page. |

Pages touchées : coque (`SiteHeader`, nouveau `NavigationLaterale`, `layout.tsx` inchangé), `components/navigation.ts`, `app/admin/layout.tsx`, `app/formateur/alertes/layout.tsx` (compteurs relus), 3 pages nouvelles ; API : module `pilotage` (service, contrôleur).

## Vérification
- API : unitaires du service (4 tests : requêtes, périmètre, conversions) ; e2e `navigation` 7 tests — accès (401, 403 apprenant, 403 administrateur sur les évaluations), chiffres exacts par formateur (brouillon, alertes traitées, alertes examinées et formation d'un autre exclus), **concordance** avec le tableau de bord du formateur, le compteur de surveillance existant et le tableau de bord administrateur, écart avant / après sur les demandes, aucune trace d'audit, 6 requêtes simultanées identiques.
- Web : tests unitaires 95 / 95 (dont 40 nouveaux : motifs, entrée active pour chaque page des deux rôles, fil d'Ariane, compteurs, regroupement) ; `tsc`, `next lint --max-warnings 0`, `next build`.
- Mutation : **10 / 10** tués (bonus d'un motif exact, poids d'un identifiant, longueur d'un motif sans joker, compteur négatif, fil d'Ariane sans menu latéral, motif du suivi retiré ; côté API : somme des alertes, livrables en correction, QCM brouillon, périmètre du formateur).
- Recette (Playwright, build de production) : menu à 1280 px (entrée active sur une sous-page, compteurs « Livrables à corriger » 2, « Alertes » 2, demandes de l'administrateur 1 / 1 / 1), réduction mémorisée après rechargement, infobulle au survol ; à 390 px : menu latéral caché, tiroir — focus sur la croix, Échap, voile, croix et navigation ferment, focus rendu au bouton menu —, aucun défilement horizontal, aucune erreur console ; captures relues (dont le tiroir : un premier essai laissait la recherche s'étirer en hauteur, corrigé).
- Suites complètes de l'API : ESLint `--max-warnings 0`, `tsc`, unitaires **130 suites / 1 671 tests**, e2e **81 suites / 940 tests** (+ 1 ignoré).
- Audit de navigation (5 rôles, 1280 et 390 px) : **114 pages, 0 problème** — le premier passage signalait « Tous les ateliers » / « Tous les QCM » sans effet visible quand les deux filtres montrent la même liste ; une ligne de résumé du filtre (lue par les lecteurs d'écran) dit désormais ce qui est affiché.
- Inventaire après la story comparé à « avant » : **295 conservées, 0 plus loin, 0 déplacée, 0 perdue** (les onglets de section de l'administrateur et les liens retirés du menu du compte sont dans le menu latéral, mêmes adresses).
