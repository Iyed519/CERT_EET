# US-UX-01 — Inventaire des fonctions et socle visuel

## En une phrase
Première story de l'épopée E11 (demande du propriétaire du 14/11/2026 : « je n'arrive pas à
distinguer une chose d'une autre ») : avant de toucher la moindre page, on relève **toutes** les
actions des espaces formateur et administrateur dans un inventaire versionné qui servira de
garde-fou à chaque story (aucune action perdue, au plus un clic de plus), puis on pose les briques
visuelles communes (icônes, quatre niveaux de bouton, menu « Plus d'actions », onglets, étapes,
sections, indicateurs cliquables, pastilles de statut, libellés humains).

## Décisions (table D, écrite avant de coder)
| # | Point | Options | Décision |
|---|---|---|---|
| D1 | Outil d'inventaire | étendre `audit-navigation.js` ; outil à part partageant la même approche | **Outil à part** `outils/recette/inventaire-actions.js` (Playwright, même connexion, même parcours par gabarit d'adresse, même liste noire de boutons) : l'audit cherche des problèmes, l'inventaire décrit ; les mélanger aurait rendu l'audit plus lent et plus fragile. Logique pure dans `inventaire-lib.js` (normalisation, gabarits, comparaison), testée par `node --test` (14 tests). |
| D2 | Ce qui est relevé | boutons et liens ; + onglets, menus, listes | `a[href]`, `button`, `[role=tab]`, `[role=menuitem]`, `summary`, `select`, `input[type=search]` visibles, hors en-tête (relevé une fois sous `(coque)`, menu du compte compris). Puis, **sans rien modifier** : chaque onglet non sélectionné, chaque menu (`aria-haspopup`, `aria-expanded=false`, volet fermé) et chaque fenêtre ouverte par un bouton sans effet destructeur ; ce qui y apparaît est noté avec une profondeur 1 et son contexte (« fenêtre « Modifier le contenu » »). Un exemplaire par libellé : les lignes d'une liste portent les mêmes boutons. Libellés normalisés (nombres → « # ») pour que l'inventaire ne dépende pas des données. |
| D3 | Règle de comparaison | même page uniquement ; tout l'espace du rôle | Une action « avant » est **conservée** si elle est atteinte depuis la même page à ≤ (profondeur avant + 1) clic, une page liée par un lien visible comptant pour un clic (cas des onglets à adresse) ; **plus loin** au-delà ; **déplacée** si elle n'existe qu'ailleurs dans l'espace du rôle ; **perdue** sinon. Correspondance : même libellé, même destination (un lien renommé qui mène à la même page), ou équivalence documentée (`docs/ux/equivalences.json`, justifiée dans le journal de la story). Échec si perdue ou plus loin. |
| D4 | Rôles et largeur | tous ; formateur + administrateur | Formateur et administrateur (le périmètre d'E11), à 1280 px (les mêmes actions existent à 390 px ; la largeur mobile est couverte par l'audit et les captures). `ROLES=apprenant` possible pour contrôler qu'un composant commun n'a rien changé côté apprenant. |
| D5 | Page de correction d'un livrable | ignorée ; atteinte | Elle n'est atteignable que par « Corriger », qui modifie des données (ouvre la correction). Sur la base locale, un livrable de démonstration a été ouvert en correction **avant** le relevé (« Reprendre » mène à la page) ; noté dans `docs/ux/README.md`. |
| D6 | Icônes | paquet npm ; SVG inline | **SVG inline** dans `components/Icone.tsx`, tracés écrits à la main pour le projet (grille 24, trait 2 px, extrémités rondes : même poids partout), `currentColor`. 72 icônes nommées par objet ou action de la plateforme. Décorative par défaut (`aria-hidden`), `libelle` sinon. Aucune dépendance ajoutée. |
| D7 | Hiérarchie des actions | nouvelles classes ; classes existantes | Les classes E10 restent (aucune page cassée) et sont documentées comme les quatre niveaux : principal `.btn` / `.btn-primary-sm`, secondaire `.btn-sm`, **discret `.btn-discret` (nouveau)**, dangereux `.btn-sm.btn-danger` + confirmation. |
| D8 | Menu « Plus d'actions » | `<details>` ; menu ARIA | Composant `MenuActions` : bouton `aria-haspopup="menu"`, liste `role="menu"` en **position fixe** (une liste dans un `.table-wrap` qui défile n'est pas coupée), placée au-dessus du bouton s'il manque de place ; clavier complet (Entrée / Espace / ↓, ↑ ↓ Origine Fin, Échap rend le focus, Tab ferme), clic extérieur, défilement et redimensionnement ferment. Variante à libellé (`libelle="Ajouter"`, `principal`) pour les menus d'ajout des stories suivantes. |
| D9 | Briques de mise en page | — | `Onglets` (à adresse : `<nav>` de liens avec `aria-current` ; dans la page : motif ARIA « tabs » + `PanneauOnglet`), compteur gris informatif ou rouge à traiter ; `Etapes` (état écrit, `aria-current="step"`, prochaine action) ; `SectionPage` (h2 + icône, carte, tons normal / accent / discret) ; `CarteIndicateur` + `GroupeIndicateurs` (carte entière cliquable, tendance, états) ; `PastilleStatut` (couleur + icône + texte, ton « brouillon » en tirets). CSS dans un bloc `US-UX-01` de `globals.css`, jetons existants seulement, contrastes en commentaire. |
| D10 | Libellés humains | traduire côté API ; dictionnaire web | **Dictionnaire web** `lib/libelles.ts` (pas de changement d'API) : 127 actions d’audit relevées dans le code de l'API, repli lisible pour un code inconnu, catégorie (connexions, comptes, formations, évaluations, certificats, IA, sécurité) ; pastille par défaut de chaque statut ; « Système » pour une action sans compte. Adoption dans les pages par US-UX-06 et US-UX-08. |
| D11 | Tests du web | aucun ; `node --test` | Règles pures (`lib/libelles.ts`, `lib/ui-regles.ts` : compteur d'onglet, étape courante) testées par `node --test` avec les types retirés par Node 22, comme `surveillance-regles.test.ts`. Nouveau script `npm run test:unitaires` (tous les `src/lib/*.test.ts`) et **une étape de plus dans le job Web de la CI** (Node 22 installé après `tsc` et `next lint`, qui restent sous Node 20). |
| D12 | Pages touchées | adopter partout ; ne rien adopter | Une seule adoption, triviale : « Activité récente » du tableau de bord administrateur affiche `libelleActionAudit(code)` au lieu du code brut — l'audit de navigation y signalait un **défilement horizontal à 390 px déjà présent sur `main`** (un code comme `ALERTES_SURVEILLANCE_CONSULTEES` ne se coupe pas). Le reste des briques est vérifié sur une page d'essai locale, non versionnée, dont deux captures vont dans `docs/guide-style/`. Arborescence et adoption : stories US-UX-02 à 08. |

## Vérification
- Outil d'inventaire : `node --test` 14 / 14 ; relevé « avant » sur `main` = `82bdf1c` (build de production, jeu de démonstration).
- Web : `npm run test:unitaires` 55 / 55 (dont 36 nouveaux) ; `tsc`, `next lint --max-warnings 0`, `next build`.
- Mutation (à la main, chaque mutant doit faire échouer un test) : comparaison sans le « + 1 » d'une page liée, voisin de profondeur 1 accepté, équivalences ignorées, déduplication retirée ; `categorieAudit` sans la règle IA avant évaluations, repli sans sigles ; `texteCompteur` qui affiche un zéro à traiter ; `etapeCourante` sur la dernière étape : **10 / 10 tués**.
- Recette des briques (page d'essai, 1280 et 390 px, captures regardées) : menu au clavier (Entrée → premier élément, ↓ saute l'élément désactivé, Échap ferme et rend le focus, Fin + Entrée déclenche l'action), clic extérieur, onglets aux flèches et Fin, aucune erreur console, aucun défilement horizontal (un premier essai débordait à 390 px : le texte masqué du compteur, en position absolue, sortait de la barre d'onglets ; la barre est maintenant le bloc de référence).
- API inchangée : ESLint `--max-warnings 0`, `tsc`, unitaires **129 suites / 1 667 tests**, e2e **80 suites / 933 tests** (+ 1 ignoré, comme avant).
- Audit de navigation (5 rôles, 1280 et 390 px, build de production) : **108 pages, 0 problème** après la correction du débordement d'« Activité récente » (le relevé sur `main` en trouvait 1).
- Inventaire relevé après la story et comparé à « avant » : 295 actions distinctes conservées, 0 déplacée, 0 perdue.
